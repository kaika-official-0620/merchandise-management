# 開花：PCとスマホ共通の業務確認表

2026-09-12。既存の開花業務をPCとiPhone・Androidから同じアカウント・在庫・取引で使うことが目的です。「メルカリのように」は端末をまたいで利用できる構成を指し、個人間売買・新しい決済制度など未決定の業務を追加する意味ではありません。料金とプランの確定は保留です。

## 確認の進め方

検証用URL、ソースの版、アプリのビルド番号、OS、確認者、日付、使った架空商品番号を記録します。PC用とスマホ用の別セッションで同じ利用者にログインし、開花担当者は別の管理者アカウントで操作します。画面更新後の反映を確認し、リアルタイム自動更新を前提にしません。

本番と別のDB・写真保存先・秘密設定を使います。通知はテスト用の宛先だけ、購入は専用テスト設定だけで確認します。検証用環境の準備だけで実通知・実購入が確認済みにはなりません。開発用の自動ログイン切替はPCの隔離プレビュー限定で、インターネット上には設けません。

各行は「成功」「要修正」「未確認」を記録します。自動テスト成功と、担当者の操作確認・実機確認は別々に残します。以下の受入結果欄は、まだ担当者が実機で確認していないため未確認です。

## 自動検証の位置付け

- `site-verification.json`：既存画面・API・権限・代表業務を隔離した実サーバーで確認。各チェックの個別結果を保持。
- `platform-sync-verification.json`：実ログインした独立したPC/app相当HTTPセッションで、登録・相互編集・預け入れ・開花の販売完了・自己販売・取消の共有データを確認。アプリの実機描画や外部受信は含まない。
- 単体/統合テスト：契約、税、保管先、通知、復元、検証環境の拒否条件などを確認。テスト数を機能数やページ数として数えない。

## 公開へ進む条件

在庫の所有者・数量・売上・税・課金・情報公開に重大な誤りがないこと、必要業務が受入済みであること、未対応の運用が担当者に明示されていることを確認します。バックアップ復旧、実機、テスト購入、通知、サポート・退会手順、規約等の準備を終えてからストア審査に進みます。ストアにテスト版を送ることと一般公開は別です。

検証用サーバーへの反映は、既存本番サービスを置き換えません。本番への切替では、現在稼働しているコミット・DB構成を確認し、既存利用者の移行、停止時間、保存、戻し方を決めてから実行します。
